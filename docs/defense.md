# Защита: воспроизводимый сценарий на 20 минут

Прочитай объяснение и пройди команды заранее. Не выдавай демо за настоящую модель:
демо проверяет runtime, а `api`-прогон показывает самостоятельные решения LLM.

## До занятия

1. Убедиться, что установлен Python 3.11+ и есть Bash.
2. Запустить `python3 -m unittest discover -s tests -v`.
3. Пройти safe-demo из сценария ниже.
4. Получить доступ к модели или запустить Ollama и пройти тот же сценарий с `--model api`.
5. Опубликовать исходники, README, policy, workspace и tests в GitHub.
6. Если репозиторий закрытый, предоставить проверяющему доступ.
7. Не загружать `.runs`, `.env`, ключи и локальные дампы с приватными данными.

## Минуты 0–3: объяснить идею и показать тесты

Смысл своими словами:

> Модель предлагает вызов инструмента, а мой runtime проверяет его и исполняет.
> Безопасность и сохранение состояния находятся вне модели. При перезапуске я
> сначала продолжаю сохранённую очередь, а уже потом спрашиваю модель снова.

Показать структуру модулей и запустить:

```bash
python3 -m unittest discover -s tests -v
```

Ожидаемый итог текущей версии: 57 тестов, `OK`.
Не нужно читать весь список вслух — выбери проверки границ и восстановления.

## Минуты 3–7: нормальный прогон с остановками

Используй новое имя запуска, если уже проходил сценарий:

```bash
cp -R workspace defense-workspace
python3 -m agent start --workspace defense-workspace --model demo --mode safe --run-id defense
```

Состояние: `wait_plan`. Покажи, что код пока исходный:

```bash
cat defense-workspace/order.py
python3 -m agent diff defense
```

Diff пустой. Затем:

```bash
python3 -m agent approve-plan defense
```

Появится подтверждение **конкретной записи** `order.py`. Задача inspect уже
выполнена. Утверждение плана не разрешило запись автоматически.

```bash
python3 -m agent approve defense
```

Теперь появится запрос на Bash:

```text
python3 -m unittest -v
cwd = .
```

```bash
python3 -m agent approve defense
python3 -m agent tasks defense
python3 -m agent diff defense
```

Ожидается `completed`, три `[x]`, изменение только `order.py`.
Показать неизменность тестов:

```bash
cmp workspace/test_order.py defense-workspace/test_order.py
```

Успешный `cmp` не печатает ничего и возвращает 0. В JSON состояния вызов
`test-bash` содержит stdout/stderr/exit_code настоящего запуска.

На реальном `api`-прогоне порядок инструментов и id могут отличаться. Это нормально:
порядок выбирает модель. Если она запросит дополнительные действия, каждый запрос
в safe снова потребует решения.

## Минуты 7–11: сбой после записи

Используй ещё одну чистую копию:

```bash
cp -R workspace crash-workspace
python3 -m agent start --workspace crash-workspace --model demo --mode safe --run-id crash
python3 -m agent approve-plan crash
python3 -m agent approve crash --crash-at after_execute
```

Последняя команда завершится кодом 99 после выполнения записи, но до сохранения
результата. Это намеренно.

```bash
cat crash-workspace/order.py
python3 -m agent resume crash
python3 -m agent uncertain-diff crash
```

Файл уже исправлен; runtime показывает `uncertain` и не делает новую запись.

```bash
python3 -m agent resolve crash retry --adopt-changes
```

Это явная новая попытка той же записи. После неё demo дойдёт до подтверждения Bash:

```bash
python3 -m agent approve crash
python3 -m agent status crash
```

В `calls.fix-write.attempts` должно быть две попытки. Побочных действий — 3:
первая запись, явный повтор записи, Bash. Сбой не вернул потраченный бюджет.

Если выбрать `fail`, runtime вернёт модели ошибку и продолжит, но фиксированный
demo-сценарий не умеет придумывать альтернативный ремонт. Для показа адаптации
используй настоящий API либо автоматический тест отказа/продолжения.

## Минуты 11–14: откат и конфликт

Сначала обычный откат ранее завершённого запуска:

```bash
python3 -m agent rollback defense
cmp workspace/order.py defense-workspace/order.py
```

Затем конфликт на другом завершённом запуске:

```bash
printf '\n# external edit\n' >> crash-workspace/order.py
python3 -m agent rollback crash
```

Ожидается ошибка конфликта. Посторонняя строка должна остаться: runtime её
не перезаписывает. Если нужно восстановить этот пример, убери **только свою
добавленную строку**, сверяя файл, после чего снова вызови rollback.

## Минуты 14–17: бюджеты и policy

Показать файл `policy.json`, затем конкретные тесты:

```bash
python3 -m unittest discover -s tests -p test_runtime.py -k budget -v
python3 -m unittest discover -s tests -p test_runtime.py -k denied -v
python3 -m unittest discover -s tests -p test_runtime.py -k escape -v
```

Бюджет на модель легко показать отдельно:

```bash
printf '{"model_calls": 0}\n' > zero-budget.json
python3 -m agent start --workspace workspace --model demo --limits zero-budget.json --run-id zero
```

Запуск остановится с `budget_exhausted` до первого запроса. Для остальных лимитов
есть независимые автотесты; не нужно вручную править сохранённый state.

## Минуты 17–20: вопросы по коду

**Почему это агент, если у тебя есть demo.py?**

Основной `api`-режим получает вызовы от модели через HTTP. Demo — тестовая замена
модели для воспроизводимости. Он проходит тот же runtime, policy и executor.
Изменения и Bash в demo настоящие, но решения заранее заданы.

**Где модель решает, а где программа?**

Модель возвращает calls или текст в `APIModel.complete`. Допуск конкретного
вызова решается в `Runtime.step`, `parse_arguments` и `Policy.check`.
Executor не общается с моделью и не выбирает следующие шаги.

**Почему модель выбрала именно read_file?**

Ей доступны описание инструмента, задача, история и текущая задача плана.
Чтение даёт данные для решения. Мы можем показать её фактический выбор в
`messages`, но не утверждаем, что знаем внутренние рассуждения модели.

**Почему недостаточно написать в prompt «не трогай тесты»?**

Prompt не является ограничением исполнения. Запись/удаление тестов дополнительно
блокирует runtime через `read_only`. При этом выполняемый Python не изолирован
на уровне ОС, и это отдельная граница безопасности.

**Может ли модель написать `bash -c` и обойти запреты?**

Нет. Проверяются вся строка, точный allow/deny, простая грамматика и закрытый
набор поддерживаемых форм. Аргументы и shell-операторы не игнорируются.

**Что будет при отказе пользователя?**

Сохранится решение. Модель получит `role: tool` с тем же id и причиной отказа.
Следующий шаг выбирается заново. Побочное действие не выполняется.

**Что если процесс упал после изменения файла?**

На диске осталось `started`; это неопределённая попытка. Автоповтора нет.
Пользователь видит diff и выбирает retry/fail/abort, а изменения при необходимости
явно относит к запуску.

**Почему нельзя повторить Bash?**

Даже тесты — программа с возможными побочными эффектами. В общем случае повтор
не идемпотентен. Можно отметить прошлую попытку неуспешной и позволить модели
предложить отдельный новый вызов с новым id.

**В чём разница нового вызова и retry?**

Retry — явно разрешённая попытка сохранённого id с теми же аргументами. Новый
вызов имеет новый id и проходит обычные проверки и подтверждения.

**Почему бюджеты переживают сбой?**

Списания и статусы сохраняются одним атомарно заменяемым JSON. После перезапуска
считывается тот же `spent`; автоматического возврата расходов нет.

**Проверка всей пачки означает атомарное исполнение пачки?**

Нет. Это атомарное принятие по ресурсам. Если после успешного допуска один
инструмент упал, предыдущие эффекты остаются в журнале. При необходимости есть
явный откат.

**Как доказать, что задача завершилась?**

Посмотреть `actual_result` и вызовы, на которые оно ссылается. Для тестирования
нужны успешный Bash/unittest и неизменившееся после него дерево. Одного текста
модели недостаточно.

**Зачем хранить байты, если есть хеш?**

Хеш нужен для сравнения. Восстановить содержимое по SHA-256 нельзя, поэтому
журнал хранит исходные байты в Base64.

**Что при внешней правке перед rollback?**

Сначала проверяются все затронутые файлы. Если хотя бы один не равен ожидаемой
последней версии, не перезаписывается ни один. Посторонние незатронутые файлы
не откатываются вообще.

**Что здесь самое слабое с точки зрения production?**

Нет изоляции ОС, защита от внешних злонамеренных гонок не заявлена, снимки
рассчитаны на маленькое дерево, исполнение последовательное, JSON-хранилище
локальное. Для учебного задания это осознанные ограничения, а не обещание
безопасно запускать произвольный чужой код.
