# Coding agent

Учебный проект для семинара «Проектирование и внедрение мультиагентных систем».

Это небольшой агент для работы с Python-кодом. Он читает файлы, предлагает
исправление и запускает тесты. Модель выбирает следующий шаг, а программа
проверяет его и выполняет. Цикл работы агента, правила доступа и сохранение
состояния написаны на Python без готовых агентских фреймворков.

Для проверки есть простой пример: в `workspace/order.py` неправильно считается
процентная скидка. Агент должен исправить расчёт и проверку диапазона скидки,
оставив `workspace/test_order.py` без изменений. Исходная ошибка в репозитории
сохранена специально, чтобы задачу можно было повторить.

## Запуск

Нужны Python 3.11+ и Bash. Подойдут macOS, Linux или WSL.
Дополнительные Python-пакеты устанавливать не нужно.
Команды выполняются из корня проекта, где лежат `README.md` и `policy.json`.

Сначала можно проверить сам проект:

```bash
python3 -m unittest discover -s tests -v
```

Ожидаемый результат — 57 тестов и `OK`.

Для быстрого знакомства есть режим `demo`. Ответы модели в нём заранее заданы,
но файлы действительно меняются, а тесты запускаются через настоящий Bash.
Работаем с копией, чтобы сохранить исходный пример:

```bash
demo_dir=$(mktemp -d /tmp/coding-agent-demo.XXXXXX)
cp -R workspace/. "$demo_dir/"
demo_run="demo-$(date +%s)"
python3 -m agent start --workspace "$demo_dir" --model demo --mode safe --run-id "$demo_run"
```

Агент покажет план и остановится. Следующие команды выполняются по очереди:

```bash
# Утвердить план
python3 -m agent approve-plan "$demo_run"

# Разрешить исправление файла
python3 -m agent approve "$demo_run"

# Разрешить запуск тестов
python3 -m agent approve "$demo_run"
```

В конце должен появиться статус `completed`.

## Настоящая модель

Агент работает с OpenAI-compatible Chat Completions API и вызовом инструментов.
Для локальной проверки использовалась Ollama с Qwen3 Instruct:

```bash
ollama pull qwen3:4b-instruct
ollama create qwen3-workshop -f examples/Ollama.Modelfile
```

Если Ollama ещё не запущена, выполни `ollama serve` в отдельном терминале.
Затем в терминале с проектом:

```bash
export OPENAI_BASE_URL='http://localhost:11434/v1/'
export OPENAI_API_KEY='ollama'
export OPENAI_MODEL='qwen3-workshop'
export OPENAI_TIMEOUT_SECONDS='120'
export OPENAI_REASONING_EFFORT='none'

real_dir=$(mktemp -d /tmp/coding-agent-real.XXXXXX)
cp -R workspace/. "$real_dir/"
real_run="real-$(date +%s)"
python3 -m agent start --workspace "$real_dir" --model api --mode safe --run-id "$real_run"
```

План и действия подтверждаются так же, как в demo, но с `"$real_run"`.
Порядок действий у настоящей модели может отличаться.

Для другого сервиса замени адрес, ключ и название модели. Убери
`OPENAI_REASONING_EFFORT`, если сервис его не поддерживает.
Настройки задаются через `export`; файл `.env` сам не загружается.
Настоящие ключи и локальные состояния `.runs` в GitHub добавлять не нужно.

## План и действия

Сначала агент может только изучать проект. Затем он предлагает план: цель,
задачи с зависимостями, нужные инструменты, риски и критерий готовности.
Запись файлов и Bash доступны после утверждения плана.

В режиме `safe` запись и Bash требуют отдельного подтверждения.
В `auto` они выполняются после проверок без отдельного подтверждения.
Удаление файлов и утверждение плана требуют решения пользователя в обоих режимах.

Доступны инструменты `list_files`, `read_file`, `write_file`, `delete_file`,
`Bash`, `submit_plan` и `finish_task`. Модель получает их описания и JSON Schema.
Программа проверяет аргументы, связь с текущей задачей и результат выполнения.
Bash возвращает stdout, stderr и код выхода.

## Основные команды

Вместо `RUN_ID` укажи идентификатор, который агент напечатал при запуске.

| Команда | Действие |
|---|---|
| `python3 -m agent status RUN_ID` | Посмотреть состояние и бюджет |
| `python3 -m agent approve-plan RUN_ID` | Утвердить план |
| `python3 -m agent reject-plan RUN_ID --reason 'Причина'` | Отклонить план |
| `python3 -m agent approve RUN_ID` | Разрешить ожидающее действие |
| `python3 -m agent deny RUN_ID --reason 'Причина'` | Отказать и передать причину модели |
| `python3 -m agent resume RUN_ID` | Продолжить тот же запуск |
| `python3 -m agent tasks RUN_ID` | Посмотреть чеклист задач |
| `python3 -m agent diff RUN_ID` | Посмотреть изменения |
| `python3 -m agent rollback RUN_ID` | Вернуть файлы к исходному состоянию |

Для новой работы нужен новый `run_id`. Чтобы продолжить старую, используй `resume`.

## Правила доступа

Настройки находятся в `policy.json`, вне workspace:

- `commands.allow` и `commands.deny` — разрешённые и запрещённые команды;
- `directories.allow` и `directories.deny` — доступные и закрытые папки;
- `read_only` — файлы, которые нельзя менять;
- `bash_timeout` и `max_output_bytes` — время работы Bash и размер его вывода.

В примере разрешены `python3 -m unittest -v`, `python3 -m unittest` и `pwd`.
Команды `rm -rf .` и `bash -c pwd` запрещены. Работать можно внутри workspace,
кроме папки `private`. Тесты защищены от записи.

Перед каждым действием проверяются полная команда, аргументы и путь.
Запрет имеет приоритет. Пути через `..` и ссылки отклоняются.
После изменения policy нужен новый запуск.
Эти правила не заменяют изоляцию ОС: Bash запускает код с правами пользователя.

## Остановка, сбой и откат

История, план, задачи, бюджет и результаты сохраняются в `.runs`.
После обычной остановки достаточно `resume`. Завершённые действия не повторяются.

Если процесс упал после действия, но до записи результата, появляется
`uncertain`. Посмотреть обнаруженные изменения можно командой:

```bash
python3 -m agent uncertain-diff RUN_ID
```

После этого нужно явно выбрать `retry`, `fail` или `abort` через
`python3 -m agent resolve RUN_ID РЕШЕНИЕ`.
Если изменения нужно отнести к запуску, добавь `--adopt-changes`.
Повтор разрешён для чтения и полной записи файла; Bash и удаление так не повторяются.
Пошаговый пример сбоя есть в [сценарии защиты](docs/defense.md).

`diff` показывает изменения конкретного запуска. `rollback` восстанавливает
только затронутые им файлы. Если после агента файл изменили вручную, откат
сообщит конфликт и не перезапишет файлы.

## Лимиты и проверка

На запуск по умолчанию даётся 40 запросов модели, 100 вызовов инструментов,
20 действий с побочным эффектом и 131072 байта результатов.
Счётчики сохраняются после остановки и сбоя.
Другие значения можно задать в JSON по образцу `examples/limits.json`:

```bash
python3 -m agent start --model demo --limits examples/limits.json
```

Прошли все 57 автотестов. Также выполнен прогон с настоящей Qwen3 Instruct:
модель исправила код и запустила оба исходных теста через Bash.
`test_order.py` остался без изменений.
Вывод тестов и diff сохранены в [examples/live-session.txt](examples/live-session.txt).
