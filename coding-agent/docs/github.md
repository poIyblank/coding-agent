# Как опубликовать и что сдавать

Нужна ссылка на репозиторий с исходниками. Один ZIP-файл в ответе преподавателю
не заменяет требуемую ссылку. В этой поставке репозиторий в вашем аккаунте
автоматически не создавался.

## Вариант через Terminal на Mac

В рабочей папке `/Users/inna/Downloads/coding-agent` Git уже настроен, а код
сохранён в коммитах. Если загружаешь именно эту папку, начинай с пункта 4,
пропусти пункт 5 и переходи к добавлению своего адреса репозитория в пункте 6.
Пункты 1–5 нужны для распакованного архива без истории Git.

1. Распакуй архив. Открой Terminal и перейди в папку `coding-agent`.
   Удобно написать `cd ` с пробелом и перетащить папку в окно Terminal.
2. Убедись, что в папке видны `README.md`, `policy.json`, `agent`, `tests`, `workspace`.
3. Запусти тесты:

```bash
python3 -m unittest discover -s tests -v
```

4. На GitHub создай новый **пустой** репозиторий, например `coding-agent`.
   Если используешь следующие команды, при создании не добавляй отдельные README,
   `.gitignore` и лицензию: README и `.gitignore` уже есть в проекте.
5. Выполни локально:

```bash
git init
git add .
git status
```

Перед коммитом просмотри `git status`: там должны быть исходники и документы.
Не должно быть `.env`, API-ключей, `.runs` и содержимого личных проектов.
Если делал копии `defense-workspace` или `crash-workspace`, не добавляй их.

```bash
git commit -m "Implement coding agent runtime"
git branch -M main
```

6. На странице своего нового репозитория скопируй его **реальный** HTTPS URL.
   В следующей команде замени `YOUR_LOGIN` на свой логин:

```bash
git remote add origin https://github.com/YOUR_LOGIN/coding-agent.git
git push -u origin main
```

`YOUR_LOGIN` — заполнитель, не готовая ссылка для сдачи. Если Git просит
авторизацию, используй штатный способ своего GitHub-клиента. Не вставляй токен
в исходники, README или сообщения чата. Пароль аккаунта для Git-over-HTTPS
не используется; можно также настроить SSH или опубликовать через GitHub Desktop.

Если Git ещё не знает автора коммитов, он сам покажет команды настройки
`user.name` и `user.email`. Укажи свои значения.

7. Обнови страницу репозитория и проверь содержимое. Открой `README.md`,
   `agent/runtime.py` и `tests/test_runtime.py`, чтобы убедиться, что загружены
   файлы, а не один архив.
8. Если репозиторий Private, добавь проверяющего в доступ по данным преподавателя.
9. В ответ на задание вставь адрес страницы репозитория вида
   `https://github.com/твой-логин/coding-agent`.

## Если не хочется настраивать Git в терминале

Можно создать репозиторий на сайте GitHub и загрузить **распакованные файлы**
через интерфейс загрузки. В корне репозитория должны оказаться папки `agent`,
`tests`, `workspace` и файлы README/policy, а не ZIP с ними. Не забудь `.gitignore`
и `.env.example`; скрытые файлы на Mac показываются сочетанием Cmd+Shift+Period.
Для автоматической проверки добавь также `.github/workflows/tests.yml`.

Для следующих обновлений удобнее Git или GitHub Desktop: меньше вероятность
случайно потерять структуру папок или загрузить секреты.

## Последняя проверка перед сдачей

- Код runtime и оба набора тестов присутствуют.
- `workspace/order.py` содержит исходную ошибку для демонстрации.
- `workspace/test_order.py` совпадает с условием.
- `policy.json` находится рядом с workspace, а не внутри него.
- Есть README с запуском, подтверждениями, восстановлением и откатом.
- Настройка окружения показана без настоящего ключа.
- Настоящий `api`-прогон сделан заранее на своей доступной модели.
- По ссылке проверяющий действительно имеет доступ к репозиторию.

Официальная справка по вариантам авторизации:
[GitHub authentication](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/about-authentication-to-github).
